# Design decisions

- Language scope: C/C++ only (BigVul; Joern's C frontend is the most mature). BigVul's language tag is unreliable; choose `.c` or `.cpp` from function syntax.
- C++ filename detection: use the dataset's `CPP`/`C++` tag or syntax markers including qualified names and C++-specific keywords (`new`, `delete`, `this`, casts, access labels, and modern language constructs). This remains a heuristic: a false positive can also fail when a C-only construct is parsed as C++, so report extraction coverage and inspect failures by language/project.
- Split by project, not by function, to prevent near-duplicate leakage.
- Hyperparameters tuned only on a validation split that is also project-disjoint from test.
- `file_name` is mostly missing, so within-project grouping uses (project, function name).
- Normalized-exact duplicates: dropped all groups with conflicting labels; kept one copy of consistent groups (global, so no exact copy crosses splits).
- Dropped vulnerable rows whose fix changes only comments/whitespace; dropped functions over 8,000 chars.
- Cross-project split: train-only projects are exactly `Chrome`, `linux`, `Android`, `savannah`, `launchpad`, `infradead`, `lysator`, `pengutronix`, `src`, `kde`, and `drm`; remaining projects are sorted then shuffled with seed 42 and assigned to test until 12% of all positives are held out, then validation until 6%, then train.
- Data source: BigVul (Fan et al., MSR 2020), original zip `MSR_data_cleaned.zip` mirrored at `huggingface.co/datasets/starsofchance/MSR_data_cleaned`; expected size 1,541,009,577 bytes and verified SHA-256 `be96d4133fe4e75a2c5dd3f36eae22939612083cd1f7bcaa3bb5ce782316e0f2`. Download with `token=False` to avoid reading the local Hugging Face token.
- Cross-project val/test rows flagged by the near-duplicate check (`near_dup_cross`) are excluded from evaluation; the flag stays in the parquet.
- Joern pilot: 60 sampled functions parsed as one folder, exported as neo4jcsv (`--repr all`); a function's graph is the AST subtree of its METHOD node plus all edges inside it. Each graph maps back to its function through the uid in its filename and graph JSON.
- Semgrep baseline: Semgrep Community Edition 1.185.0 with the frozen `p/c` YAML snapshot in `configs/semgrep_c.yml` (SHA-256 `71e7aa2e2611f937ad5e4be7ba12bdb93c188c1de6db30be5b24aeb5b3c395ff`). The two C rules are duplicated for Semgrep's `cpp` parser with only the language field and rule ID changed; the derived overlay hash is `2b21aba70d1d913db9a47cbf11d0065e2bef58cc437a46d2368494495a5e5406`, and the effective ruleset hash is `a936fb1c81084c67f6b0a988fd61f26824e3b3ffd7df6ec369b246300a985660`. It produced zero alerts on both fixed test sets, scanned all 18,211 within-project and 23,867 eligible cross-project functions, and reported 68/167 parser warnings. Exclude `near_dup_cross` rows from cross-project evaluation; describe the result as a narrow baseline, not broad C/C++ coverage.
- Initial Phase 2 text baseline (`results/baseline_results.csv`): validation-tuned raw-token TF-IDF + logistic regression. Its test AP is reproduced in Phase 2A exactly (within 0.356322; cross 0.104735), with the pre-rerun CSV preserved as `results/baseline_results_v1.csv`.
- Graph workset: preserve the original split fields; include all vulnerable functions, all within-project val/test rows, all non-near-duplicate cross-project val/test rows, and a seeded uniform sample of 5 safe training functions per vulnerable training function for each split. Default Joern batch size is 1,000. The planner's selection coverage is not parser coverage; report Joern success/failure separately after extraction.
- Graph extraction acceptance: after the complete Joern run, independently verify manifest/status coverage, graph/status one-to-one mapping, metadata and label consistency, edge bounds, and truncation arithmetic before CodeBERT feature generation.
- Kaggle input bundle: `scripts/package_kaggle_inputs.py` includes the cleaned parquet, Joern CLI, `src/`, and `scripts/run_graph_pipeline.py`, so the uploaded archive is self-contained for extraction. The output graph bundle omits bulky Joern source/export scratch files; on resume, `run_cpg_batches.py --data ...` reconstructs only missing source snippets for batches that need rerunning.
- Kaggle extraction entry point: `scripts/run_graph_pipeline.py` prepares the workset when absent, runs the existing resumable Joern batch runner, performs the independent audit, and optionally bundles only compact graph and audit outputs. A one-batch `--limit-batches 1` run is a partial smoke audit; full acceptance still requires the full-workset audit to report `complete: true` and zero errors.
- Joern batch runner smoke: four functions were passed through the real CLI using Java 21; it produced three graphs (both C++ samples and one C sample). One C sample had no matching METHOD node, a plausible macro/signature parse limitation. The smoke also exposed and fixed a relative Joern-path bug and coverage-reporting errors before full extraction. This is functional evidence only, not a dataset-level coverage estimate.
- PyG feature encoding: concatenate one-hot Joern node types and frozen CodeBERT CLS vectors (float16 storage); keep edge indices/types, source line numbers and labels in sharded PyG `Data` objects. Provide an identifier-masked text variant using the same keyword-aware tokenizer as the text baseline. These converters are prepared but full extraction and feature encoding remain unrun.
- Initial GNN: relational graph convolution over AST, CFG, REACHING_DEF and CDG relations; residual self transforms and mean/max graph readout. Training uses weighted BCE, warmup plus cosine learning-rate decay, early stopping on validation AP, and optional Optuna tuning on validation only. Single-edge ablations remove one relation type at message-passing time. Final evaluation reports project-cluster AP intervals and per-project metrics only when a project has at least 30 vulnerable test functions. The training driver is prepared but not run until the PyG data is built.
- Localization: use absolute input-gradient saliency, sum node importance by Joern line number, and score vulnerable test functions against changed `func_before` lines. Fix-only inserted lines map to the adjacent pre-fix source line. Compare top-1/3/5 line hits with repeated uniform draws from the graph's line-mapped lines; report localization coverage separately.
- Model comparison: join by `norm_hash` and compare only the shared graph-covered test rows. Baseline IDs were attached after verifying each saved score group against the matching split's labels and row count. Semgrep is compared at its fixed alert point; with zero recall, matched-recall precision is not defined.
- Phase 2A baseline reproduction: preserve the pre-rerun text result table as `results/baseline_results_v1.csv`; rerunning the validation-only C grid reproduces its saved TF-IDF test AP exactly (within 0.356322 and cross 0.104735).
- Phase 2A Semgrep version: use the already-installed venv package `semgrep==1.185.0`; do not install a second copy. Record the local version through package metadata because the bare CLI version command can fail while initializing TLS in this restricted shell.
- Phase 2A Semgrep rules: use the frozen local `p/c` C-rule snapshot in `configs/semgrep_c.yml` plus deterministic C++ language copies. The snapshot and derived rules are local, hash recorded, and run without registry access; this is preferred here over a mutable online ruleset, though it is not a pinned clone commit.
- Phase 2A Semgrep operating points: (1) flag any finding; (2) flag findings whose rule metadata is security-related or whose severity is WARNING/ERROR. The frozen four-rule effective set makes these points identical because both source rules are tagged security and have WARNING/ERROR severity.
- Phase 2A Semgrep error scoring: retain every eligible test function; if Semgrep emits no finding, score the function unflagged even when a parser warning or per-rule timeout is recorded. A process-level batch failure stops the run before baseline metrics are written.
- Phase 2A Semgrep resource bounds: scan 1,000 files per batch with Semgrep's per-rule `--timeout=2`, `--timeout-threshold=1`, `--max-memory=512` MiB and `--jobs=1`; stage source snippets under the system temp directory and keep durable batches/reports under `results/`. A failed CLI batch is logged and stops the run; completed batches stay cached so a corrected rerun resumes without rescanning them. CLI flags are checked against the official reference at `https://semgrep.dev/docs/cli-reference/`.
- Phase 2A identifier ablation: keep the raw tokenizer as the reference; API-preserving masking maps non-keyword, non-allow-listed identifiers to per-function `ID_n` tokens and maps numeric/string/character literals to `NUM`/`STR`; full masking also replaces library/API names.
- Phase 2A uncertainty: use 200 cluster bootstrap resamples for the reported AP intervals, resampling `project_g` for cross-project and `group` for within-project; retain the row-level bootstrap as an explicitly optimistic comparator only.
- Phase 2A final artifacts: `scripts/run_baselines.sh` writes `results/baselines_v2.csv`, tuning/scores/per-project tables, cluster-vs-row bootstrap comparison, PR curves, AP/prevalence chart, and a <=10-line conclusion. The script forces Matplotlib Agg for headless macOS execution and resumes Semgrep JSON batches by fingerprint.
- Phase 2A observed Semgrep coverage: 18,211/18,211 within and 23,867/23,867 cross snippets scanned; 68 and 167 parser-error files respectively; zero timeouts, process crashes, or findings. With all test rows retained, parser-warning files are scored unflagged if they produce no finding.
- Phase 2A Cppcheck baseline: version 2.22.0, per-file timeout 2 seconds, fixed operating point flags any warning/error finding, same C/C++ extension heuristic as Semgrep. On 18,211 within-project test functions it flagged 1,113, including 359 syntax-error files; precision/recall/F1 were 0.0800/0.1034/0.0902. On 23,867 eligible cross-project test functions it flagged 2,053, including 213 syntax-error files; precision/recall/F1 were 0.0828/0.1605/0.1093. There were zero timeouts and crashes. A `syntaxError` diagnostic is an error-severity finding and therefore counts as flagged; retain the parse-failure count to expose parser-induced alert risk. Per-function JSONL records and the exact settings are under `results/cppcheck/full/`.
- Phase 2A masking result: API-preserving and fully masked text improve cross-project AP over raw-token text in this single seed, while both sharply reduce within-project AP. This is consistent with vocabulary sensitivity but does not identify project memorization as the cause.
- Data-integrity incident and recovery: importing the former `data.make_splits` module executed its top-level cleaning/split workflow and rewrote the processed parquet without the near-duplicate columns. The pre-recovery copy is `/private/tmp/gnn-parquet-recovery.frdcAw/current_without_flags.parquet` (SHA-256 `6eaaade604e72844930c31c30b24c4cbd5842b0f81bbd0531d990f23a723adc2`); the flags were recomputed by the unchanged `near_dup_check.py` implementation in the separate temp tree. Current restored parquet SHA-256 is `239c3c622f641515aff2d2d45e51f9ee2e72c8ba6c810c3a62a5864ab4acc50f`. PyArrow reopened both copies; all 15 original columns and row order match the backup exactly, both flags match the recomputed file exactly, and invariants pass: 182,100 rows, 8,609 positives, 295 projects, unique `norm_hash`, identical aliases/splits/labels, 23,867 eligible cross-test rows and 1,059 positives. Flag counts are cross val/test 21/59 (1/2 vulnerable) and within val/test 513/474 (17/16 vulnerable). No cleaning, aliases, split assignments, seed or MinHash parameters changed.
- Import safety: workflows in `data.make_splits`, `data.near_dup_check`, `data.prepare_bigvul`, the data inspectors, legacy TF-IDF baseline, legacy figure generator and Joern pilot sample/extractor/renderer are now behind `main()` guards. Importing them from an isolated temporary working directory succeeded without creating `data/` or `results/`. The pilot sample generator refuses to overwrite an existing pilot directory or manifest.
- Graph schema leakage: `build_pyg_dataset.py` now creates a fixed node-type vocabulary from rows whose split roles are training in both settings (`split_within == train` and `split_cross == train`); it does not read vulnerability labels to construct that vocabulary. Unknown types use the reserved `__UNK__` feature slot. The graph JSONL format is unchanged; the PyG dataset schema version was incremented. No PyG feature artifacts existed when this change was made.
- Remaining graph risks: C++ extension detection can match C++ syntax inside comments; METHOD matching relies on uid text in Joern's FILENAME and the largest candidate AST subtree; breadth-first truncation may remove later nodes/edges. These are documented limitations and require full-run failure/truncation reports. Failed Joern attempts retain their logs, CPG and CSV export for diagnosis; successful conversions remove their temporary export only after compact graphs are written. Every failed function receives a status and reason.
